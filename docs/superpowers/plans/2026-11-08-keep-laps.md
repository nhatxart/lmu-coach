# Keep Laps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep chosen laps of a recording as small stand-alone files in the kept-laps folder (checked before anything else happens), then optionally delete the original, without kept laps counting twice in grip profiles or topography.

**Architecture:** The backend owns every lap rule: it cuts a lap into a recorder-schema `.duckdb` (`lap_cut.py`, streamed by a read-only endpoint, with the original's tyre-model context in metadata) and its readers treat a kept file as exactly one lap. The host agent (`recorder_control.py`, the only process that may write host folders) fetches the cut, writes it atomically into the kept-laps folder, has the backend check it, and deletes an original only on explicit request after proving it writes where Docker reads. The UI adds a keep mode on the lap bar, a results dialog and the delete offer.

**Tech Stack:** Python 3.12 backend (FastAPI, DuckDB, numpy; pytest), host agent Python 3.11+ (FastAPI, DuckDB, urllib only), single-file UI (`index.html`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-keep-laps-and-lap-comparison-design.md` §4 (and §2 anti-goals, §8 calls). Visual reference only: branch `spike/compare-mockup` (`b83a068`), search `const KEEP=` in its `index.html`.

## Global Constraints

- PowerShell: chain with `;`, never `&&`. Never modify `.env`, `lmu-coach.config.json`, or anything in the real `data/` folders; tests use tmp dirs. Never delete a file the code did not create, except the one original the user confirmed.
- Nothing is deleted before every kept file of that action passed its check; delete asks twice in the UI; "Keep the recording" is the default button.
- A recording is never modified in place. Kept files are new files written as `.<name>.tmp` then `os.replace`.
- Kept file = one lap: `lap_cut.MARGIN_S = 3.0` seconds of data before the start crossing and after the end crossing (clamped to the recording), recorder schema (same tables, `channelsList` / `eventsList`, metadata copied).
- Kept-file metadata keys (exact): `KeptFromFile` (original file name), `KeptLap` (int as string), `KeptLapTime` (official lap time, 3 decimals), `KeptAt` (UTC ISO `YYYY-MM-DDTHH:MM:SSZ`), `GateOrigin` (the original's first `GPS Time` value, repr float), `KeptTyreContext` (JSON, see Task 3).
- Kept file name (ruling, replaces the spec §8 "`<Track> - <Car> - …`" call so every existing name parser keeps working: `parseSession`, ingest's date regex, `build_track_reference`'s track split): `<_safe(track)>-<_safe(car)> L<n> <m>m<ss.sss>-<original's YYYY-MM-DDTHH_MM_SSZ stamp>.duckdb`, e.g. `Fuji Speedway-Team WRT 2026 _69_LM L9 1m42.983-2026-10-19T23_18_37Z.duckdb`; `_safe` = the recorder's (`recorder.py` `_safe`: alphanumerics and ` -_` kept, others → `_`). Deterministic per (original, lap), so keeping a lap twice finds the existing file.
- The check (spec §4.2): the backend reads the kept file and lists exactly one lap, number `n`, `complete`, with `lap_time_s` equal to the original's within 0.001 s.
- Only recorder files can be kept (metadata `RecordedBy` starts with `lmu-coach-recorder`); native LMU exports and files in the kept-laps folder are refused with a reason (UI disabled, backend 422, agent 400).
- Host agent: new config keys `host_agent.backend_url` (default `"http://localhost:8080"`); folders resolve as: kept = `stack_paths.reference_laps_dir` or `<repo>/data/reference_laps`; sessions = `recorder.output_dir`, else `stack_paths.lmu_telemetry_dir`, else `<repo>/data/sessions` (the recorder's default). New keys must be added to `DEFAULT_CONFIG` (unknown keys are dropped). Endpoints are POST (CORS allows GET/POST/PUT only) behind `GuardMiddleware`; file names are bare names (no separators, no `..`, must end `.duckdb`, must exist where required).
- Comment the why (`PREVIOUSLY … Fix:` for changed behaviour). Commit: `git -c user.name=hoang -c user.email=hoangnhatvn2002@gmail.com commit -F <msgfile>` (UTF-8 without BOM), message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests (repo root): backend `uv run --no-project --with pytest --with fastapi --with duckdb --with numpy --with scipy --with httpx --with pydantic --with "uvicorn[standard]" python -m pytest backend/tests -q --ignore=backend/tests/ui`; UI `… --with playwright python -m pytest backend/tests/ui -q`; recorder `cd recorder; uv run python -m unittest test_recorder -v`.

## Review Focus

1. A cut that starts just after skipped game ticks (the 10 Hz gate replays from the file's first row): the kept file's 10 Hz times must equal the original's for the same rows. (Task 1 `test_gate_origin_keeps_slow_axis`, Task 2 `test_cut_after_skipped_ticks_keeps_positions`)
2. Keeping lap 0 (no data before its crossing) or the last complete lap (a short tail): margins clamp, the file still reads as exactly that lap. (Task 2 `test_cut_first_and_last_lap_clamp_margins`)
3. Deleting an original that the backend or another program has open (Windows lock): a clear "in use, try again" error, the file stays. (Task 5 `test_delete_locked_file_reports_in_use`)
4. Agent's kept folder is not the folder Docker mounts (empty or wrong `reference_laps_dir`): keep is refused with the reason before anything is written there. (Task 5 `test_keep_refused_when_folders_differ`)
5. Hostile or odd file names (`..\x.duckdb`, `C:\x.duckdb`, `a/b.duckdb`, `x.txt`, a kept file as the source): 400 in agent, 400/422 in backend, nothing read or written outside the folders. (Task 2 `test_cut_rejects_bad_names`, Task 5 `test_agent_rejects_bad_names`)

### Task 2: `lap_cut.py` and the cut endpoint

**Files:** Create `backend/app/lap_cut.py`, `backend/tests/test_lap_cut.py`; Modify `backend/app/main.py`.

**Interfaces:**
- Consumes: Task 1 readers; `telemetry.session_time_axes`, `channel_time`, `_read_channel_frequencies`, `lap_index`.
- Produces: `MARGIN_S = 3.0`; `@dataclass(frozen=True) CutInfo(name: str, lap: int, lap_time_s: float, t_start: float, t_end: float)`; `kept_name(src_name: str, meta: dict, lap: int, lap_time_s: float) -> str`; `cut_lap(src: Path, lap: int, dst: Path, tyre_context: dict | None) -> CutInfo` (raises `CutError(str)` for: not a recorder file, a kept file, lap missing/incomplete). Route `GET /sessions/sessions/{file}/laps/{lap}/cut` → 200 `application/octet-stream` body = the cut file (built in a temp dir, deleted after the response), headers `X-Kept-Name`, `X-Kept-Lap-Time`; 400 bad name (via `_resolve_file`), 404 missing, 422 `CutError` with its message. (Tyre context comes from Task 3; until then the route passes `None` and writes `KeptTyreContext` = `{}`.)
- Rules: rows chosen by game time, not index: each scalar/wheel table by its own time axis (`channel_time` with the session axes); keep rows with t in [t_start − 3, t_end + 3] clamped; event tables (`ABS`, `TC`, `Gear`, `In Pits`) keep rows in the window plus one seed row at the window start carrying the last value before it; `Lap` keeps rows n and n+1 only; `Lap Time` keeps lap n's row; `Other Cars` by `ts`; `unpopulated_by_lmu` tables stay empty; `channelsList` / `eventsList` copied unchanged; metadata copied plus the Global-Constraints keys (`TotalSamples`, `LapCount` updated). Written `.<name>.tmp` then `os.replace`.
- [ ] Step 1: failing tests:

  - `test_cut_trackmap_matches_original_lap`: `/trackmap` of the cut vs the original's lap n: `driven_line.x/z` within 0.05 m, `t` within 0.011 s, `lap_dist` within 0.5 m, `speed/throttle/brake` within 1e-6 at matching points; `coordinate_origin` equal.

  - `test_cut_first_and_last_lap_clamp_margins` (Review Focus 2).

  - `test_cut_refuses_native_and_kept` (422 messages) and `test_cut_rejects_bad_names` (Review Focus 5).
