# Keep Laps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep chosen laps of a recording as small stand-alone files in the kept-laps folder (each checked before anything else happens), then, only after a deliberate Delete button and a warning, delete the original, without kept laps counting twice in grip profiles or topography.

**Architecture:** Everything runs in the backend (no host agent, no LLM; spec §4.4a). `lap_cut.py` cuts a lap into a recorder-schema `.duckdb` with the original's tyre-model context in metadata; a keep endpoint writes it into `/data/reference_laps` and re-reads it as the check; the readers treat a kept file as exactly one lap. A delete endpoint removes an original from `/data/sessions` only with an explicit confirmation and checked kept files. `docker-compose.yml` mounts both folders read-write. The UI adds a keep mode on the lap bar, a results dialog and the Delete button with its warning.

**Tech Stack:** Python 3.12 backend (FastAPI, DuckDB, numpy; pytest), single-file UI (`index.html`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-keep-laps-and-lap-comparison-design.md` §4 with the §4.4a amendment (and §2 anti-goals, §8 calls). Visual reference only: branch `spike/compare-mockup` (`b83a068`), search `const KEEP=` in its `index.html`.

## Global Constraints

- PowerShell: chain with `;`, never `&&`. Never modify `.env`, `lmu-coach.config.json`, or anything in the real `data/` folders; tests use tmp dirs. Code never deletes a file it did not create, except the one original the user confirmed.
- Nothing is deleted before every kept file of that action passed its check. Delete is a separate, deliberate step: a "Delete recording…" button (never the default), then a warning naming the file and what is lost, confirmed with a second button "Delete permanently"; the request carries `"confirm": "<exact file name>"`.
- A recording is never modified in place. Kept files are written as `.<name>.tmp` in the kept folder, then `os.replace`.
- Kept file = one lap: `lap_cut.MARGIN_S = 3.0` seconds before the start crossing and after the end crossing (clamped to the recording), recorder schema (same tables, `channelsList` / `eventsList`, metadata copied).
- Kept-file metadata keys (exact): `KeptFromFile` (original file name), `KeptLap` (int as string), `KeptLapTime` (official lap time, 3 decimals), `KeptAt` (UTC `YYYY-MM-DDTHH:MM:SSZ`), `GateDue` (the original's 10 Hz gate due time at the kept file's first row, repr float), `KeptTyreContext` (JSON, Task 3). AMENDED 11/10/2026 (Task 1 review: the original's 10 Hz gate restarts after every clock jump, so replaying from its first row is silently wrong after a jump): `GateDue` replaces `GateOrigin` = the original's 10 Hz gate due time at the kept file's first row (repr float), computed by a helper shared by the writer (Task 2) and the reader (Task 1); the reader replays from it and uses it only when it is < the first GPS Time + 0.1 s and the replayed row count matches the 10 Hz tables.
- Kept file name (user-approved): `<_safe(track)>-<_safe(car)> L<n> <m>m<ss.sss>-<original's YYYY-MM-DDTHH_MM_SSZ stamp>.duckdb`, e.g. `Fuji Speedway-Team WRT 2026 _69_LM L9 1m42.983-2026-10-19T23_18_37Z.duckdb`; `_safe` as in `recorder.py` (alphanumerics and ` -_` kept, others → `_`). Deterministic per (original, lap), so keeping a lap twice finds the existing file (`already_kept`, still checked, not rewritten).
- The check (spec §4.2): the backend re-reads the kept file: exactly one lap, number `n`, `complete`, `lap_time_s` equal to the original's within 0.001 s. A failed check removes only the file this request just wrote.
- Only recorder files are kept (metadata `RecordedBy` starts with `lmu-coach-recorder`, file in the sessions folder); native LMU exports and kept files are refused with a reason (UI disabled, API 422).
- File names in URLs and bodies are bare names: no separators, no `..`, must end `.duckdb`; resolved only inside `OWN_SESSIONS_DIR` / `REFERENCE_LAPS_DIR` (reuse `_resolve_file`).
- `docker-compose.yml`: `/data/sessions` and `/data/reference_laps` mounts lose `:ro`, with a comment why (keep laps writes, deliberate delete removes); `/data/track_reference` stays `:ro`.
- Comment the why (`PREVIOUSLY … Fix:` for changed behaviour). Commit: `git -c user.name=hoang -c user.email=hoangnhatvn2002@gmail.com commit -F <msgfile>` (UTF-8 without BOM), message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests (repo root): backend `uv run --no-project --with pytest --with fastapi --with duckdb --with numpy --with scipy --with httpx --with pydantic python -m pytest backend/tests -q --ignore=backend/tests/ui`; UI `… --with "uvicorn[standard]" --with playwright python -m pytest backend/tests/ui -q`.

## Review Focus

1. A cut that starts just after skipped game ticks (the 10 Hz gate replays from the file's first row): the kept file's 10 Hz times must equal the original's for the same rows. (Task 1 `test_gate_origin_keeps_slow_axis`, Task 2 `test_cut_after_skipped_ticks_keeps_positions`)
2. Keeping lap 0 (no data before its crossing) or the last complete lap (a short tail): margins clamp, the file still reads as exactly that lap. (Task 2 `test_cut_first_and_last_lap_clamp_margins`)
3. Deleting an original that is open elsewhere (the game's recorder, a viewer; Windows lock): a clear "in use, try again" error, the file stays. (Task 5 `test_delete_locked_file_reports_in_use`)
4. The kept-laps folder is not writable (an old compose with `:ro`, permissions): keep returns the reason ("The kept-laps folder is read-only: rebuild with the new docker-compose.yml"), nothing half-written stays. (Task 2 `test_keep_reports_read_only_folder`)
5. Hostile or odd names (`..\x.duckdb`, `C:\x.duckdb`, `a/b.duckdb`, `x.txt`, a kept file as the source, a confirm that differs by case or whitespace): 400/422, nothing read, written or deleted outside the folders. (Task 2 `test_keep_rejects_bad_names`, Task 5 `test_delete_rejects_bad_names_and_confirm`)
