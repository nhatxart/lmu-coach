Findings:
- The grip PROXY is right: on both cars with game forces it tracks the game's mu at r 0.97, the binned curve shapes match (r 0.94-0.999) and peak slip angles agree within one 0.4 deg bin except Cadillac front (0.8 deg). Rear proxy reads ~3-14 % high.
- The CURVE is an average, not a predictor: inside the cornering range slip angle explains 0-34 % of sample-to-sample grip (front better than rear). Grip at a given slip angle varies a lot with speed, load, temperature and combined slip. So GU ("where on the curve") is defensible; reading the curve as "grip you would get at X deg" is not, at the sample level.
- PEAKS ARE MOSTLY NOT FOUND: WRT never got past the peak in any bootstrap (and ran 33 C below optimal tyre temp - a cold-tyre curve); Aston only in 11-16 % of resamples. The peak is a lower bound most of the time, as the model already says.

#### Recorder polling (10/21/2026) - tick-sync was NOT kept as the default, see the next section
- Problem: the HF1 recorder polled at a fixed 1000 Hz. That busy-waits (one core 99 %, measured) and copies the whole 317 KiB shared-memory block on every poll (~22 us each with the real MMapControl: 2 % of a core, but 325 MB/s of memory traffic at 1000 Hz; the busy-wait was the bigger cost). LMU stuttered even on an undervolted 9800X3D with SMT off.
- Fix: `TickSync` in recorder.py, now the default. It sleeps to just before the next ~10 ms game update (period learned from the arrivals), then watches the player's `mElapsedTime` in the LIVE memory every ~1 ms (`peek_elapsed_time`, one double, no copy) and copies the block only when the clock moved: ~100 copies/s (0.2 % of a core, 33 MB/s). If the clock does not move for 50 ms (pause, menu, loading) it polls anyway so the freeze/garage detection keeps running; if the live clock cannot be read it degrades to one timed poll per expected tick. `--poll-hz N` brings back fixed-rate polling; `--every-poll` implies it. The recorder also lowers itself to below-normal priority (`--normal-priority` to opt out).
- Unchanged on purpose: every row is stamped with the game's `mElapsedTime` (timed replay, map alignment, lap cutting, body slip and the yaw filters all use it) and lap times come from the game's `mLastLapTime` (1 ms). New in the file: `PollMode` (`tick-sync` / `fixed`) and `SkippedTicks` (clock steps >= 15 ms) in `metadata`; `PollHz` is the nominal 100 in tick mode.
- Checked: recorder tests 51 OK (TickSync with a fake clock: few looks per tick, no missed tick over 100, gives up when frozen, learns a 10.4 ms game, falls back without a live clock; loop test with a fake game: one full copy per tick, looks in between).
